## Краткий аудит текущего состояния

- **Один файл на всё**: парсинг конфига, сеть, процесс-менеджмент, логирование, тесты — в одном скрипте с case-диспетчером. Работает, но плохо тестируется по частям и сложно расширять.
- **Конфиг живёт в `$HOME`** отдельно от скрипта и раннтайм-файлов — нет единого места, куда можно "положить проект и убрать".
- **Кэш IP-листов уже частично есть** (`ALLOWED_IPS_CACHE`), но это побочный продукт, не полноценный кэш: нет TTL, нет fallback при сетевой ошибке — если `curl` не смог скачать список, вы либо падаете в `die`, либо (если хоть что-то скачалось) работаете с неполным списком без предупреждения о степени свежести.
- **Нет версионирования/истории** — если список IP резко изменится или сайт пропадёт из выдачи, отследить это нельзя.
- **Логика раскидана нелинейно**: `do_test` знает про credentials прокси, `do_status` знает про сеть, `build_allowed_ips` знает про curl — границы ответственности смазаны, что и создало недавний баг с кавычками (правка парсинга задела совершенно не связанную с ним часть).

## Целевая структура проекта

```
amnezia-proxy/
├── bin/
│   └── amnezia-proxy              # единая точка входа (тонкий диспетчер)
├── lib/
│   ├── config.sh                  # load_config, trim, strip_quotes
│   ├── network.sh                 # build_allowed_ips, кэш, wg-конфиг
│   ├── proxy.sh                   # 3proxy: generate/start/stop
│   ├── tunnel.sh                  # awg-quick: start/stop/status
│   └── log.sh                     # log(), die()
├── config/
│   ├── amnezia-proxy.conf.example # шаблон с комментариями, без секретов
│   └── amnezia-proxy.conf         # реальный конфиг (в .gitignore)
├── var/
│   ├── cache/
│   │   └── allowed_ips.txt        # + allowed_ips.meta (таймстамп, источник)
│   ├── run/
│   │   ├── 3proxy.pid
│   │   └── amnw0.conf              # временный WG-конфиг
│   └── log/
│       └── manager.log
├── tests/
│   └── test_config.sh             # юнит-тесты на trim/strip_quotes/парсинг
└── README.md
```

Идея: **один корневой каталог проекта**, который можно целиком перенести/забэкапить/положить в git (кроме `config/amnezia-proxy.conf` и `var/`, которые в `.gitignore`). Скрипт сам вычисляет свой `PROJECT_ROOT` через `$(dirname "$(readlink -f "$0")")/..` вместо жёстко зашитых путей в `$HOME`.

## Разделение на модули

Не "разные скрипты, которые пользователь вызывает по отдельности", а **один входной CLI + подключаемые библиотеки** через `source`. Так сохраняется удобство одной команды (`amnezia-proxy start`), но код разбит по ответственности:

- `bin/amnezia-proxy` — только `case "$1"` и `source lib/*.sh`, ноль бизнес-логики
- `lib/config.sh` — всё, что было багом на прошлой неделе, теперь изолировано и тестируется отдельно от сети/процессов
- `lib/network.sh` — отдельно кэш, отдельно генерация WG-конфига
- `lib/proxy.sh` / `lib/tunnel.sh` — по одному внешнему инструменту на файл (3proxy vs awg-quick), не смешивать

Это не меняет способ запуска для вас — `amnezia-proxy start/stop/status` работает как раньше, но правка одной части (например, кэша) физически не может задеть парсинг конфига, как случилось в прошлый раз.

## Кэширование AllowedIPs — конкретно

Текущее поведение: скачал → если пусто → `die`. Предлагаю:

1. **TTL на кэш** (например, 6-24 часа, настраивается в конфиге `IPLIST_CACHE_TTL`). Если кэш свежий — не дёргаем сеть вообще при каждом `start`.
2. **Метафайл рядом с кэшем** (`allowed_ips.meta`): таймстамп последнего успешного обновления + список источников, которые ответили/не ответили.
3. **Graceful fallback**: если сеть недоступна или часть URL не отвечает — используем последний рабочий кэш с явным `WARN "используется кэш возрастом Nh, обновить не удалось"`, а не падаем в `die`, если кэш вообще не пуст. `die` оставить только для случая "кэша нет вообще и сеть недоступна".
4. **Условная загрузка** (опционально, ниже приоритетом): `curl --etag-save/--etag-compare`, чтобы не перекачивать список, если сервер отдаёт тот же ETag — экономит трафик при частых рестартах.

## План доработок (по приоритету)

1. **Реструктуризация каталогов + вынос путей из `$HOME` в `PROJECT_ROOT`** — база для всего остального, без этого остальные пункты просто множат файлы в разных местах
2. **Разбивка на `lib/*.sh`** — чисто механический рефакторинг существующей логики, без изменения поведения
3. **TTL-кэш для AllowedIPs с fallback** — прямое улучшение надёжности (сейчас любой сбой сети при `start` = полный отказ)
4. **`config.conf.example`** с комментариями по каждой переменной (включая `WG_MTU`, `Jc/Jmin/Jmax`) — снимает необходимость держать в голове, что значит каждое поле
5. **`tests/test_config.sh`** — юнит-тест на `trim`/`strip_quotes`/парсинг с кавычками и без, чтобы баг вроде прошлого ловился до продакшена, а не в логах после `start`
6. **(опционально) systemd unit**, вызывающий `bin/amnezia-proxy` как `ExecStartPre`/`ExecStopPost` — обсуждали раньше, отдельный шаг, не блокирует остальное
