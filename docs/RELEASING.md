# Подготовка релиза

Архив содержит Bash/Python-код Linux-версии; AWG, 3proxy и остальные системные
зависимости пользователь устанавливает отдельно. Нативных бинарников в архиве
нет. Лицензия проекта — MIT; внешние программы сохраняют собственные лицензии.

## Локальная сборка

Требуются Python 3 и make:

```bash
make check-dist
make dist
(cd dist && sha256sum --check ./*.sha256)
```

Версия читается из VERSION в bin/amnezia-proxy. Для неё обязателен раздел в
CHANGELOG.md. Текущая подготовленная версия — 0.3.1. Наличие локального архива само по себе не означает,
что тег отправлен или публичный релиз создан.

Результат: `dist/apm-<версия>-linux.tar.gz` и одноимённый файл `.sha256`.
Внутри — один каталог с версией и RELEASE.json: платформа, лицензия, SHA256
и права каждого файла. Состав задаётся явно; локальные конфиги, .git, тесты,
внутренние отчёты аудита, планы из docs/tasks, кэш и runtime не попадают в архив. LICENSE включена также в установленную
документацию.

SOURCE_DATE_EPOCH задаёт время метаданных (default 0), DISTDIR — каталог вывода.
UID/GID, порядок, права, tar/gzip-метаданные нормализуются. Для одинакового
содержимого и одинакового окружения Python/zlib архив воспроизводим независимо
от времени исходных файлов и пути checkout. SHA256 подтверждает целостность,
но не заменяет доверенный канал получения или подпись автора.

`check-dist` — разработческая проверка из checkout. В самом архиве тестов нет,
но `make dist` позволяет пересобрать тот же архив из распакованной поставки.

## Проверка пользователем

```bash
sha256sum --check apm-0.3.1-linux.tar.gz.sha256
tar -xzf apm-0.3.1-linux.tar.gz
cd apm-0.3.1-linux
make install
export PATH="$HOME/.local/bin:$PATH"
apm --version
apm config init
```

Затем заполнить конфиг, выполнить config validate и doctor, проверить выбранный
режим и GUI, завершить stop. Обновление, откат и удаление описаны в
[инструкции установки](INSTALLATION.md).

## Перед публикацией

- Проверить версию CLI и changelog; перейти на новую версию до сборки нового выпуска.
- Получить успешные lint, Docker tests и Release archive jobs для выбранного коммита.
- Пройти ручную приёмку настоящих VPN-only/proxy-only/combined, недоступного VPN,
  GUI и stop; пропущенные namespace-тесты не считать подтверждением защиты.
- Проверить архив на чистом Linux по пользовательской инструкции.
- Собрать из выбранного коммита архив и checksum. После согласования создать тег
  и публичный релиз с этими файлами и описанием изменений.

Тег ставится на конкретный коммит, который прошёл CI, а не автоматически на
текущий HEAD. Например, после успешного CI для релизного коммита:

```bash
git tag -a v0.3.1 <проверенный-коммит> -m "apm v0.3.1"
git push origin refs/tags/v0.3.1
```

Существующий v0.3.0 не перемещается. Теги, push и публикация не выполняются
командами make dist/check-dist.
