# Конфигурация и переменные окружения

[Быстрый старт](../README.md) · [Шаблон](../config.example) · [Технический справочник](REFERENCE.md)

Здесь перечислены все поддерживаемые ключи пользовательского конфига и публичные
переменные окружения. Внутренние переменные Bash не являются настройками.

## Выбор файла и формат

Порядок выбора: `--config ПУТЬ` → `AMNEZIA_PROXY_CONFIG` →
`${XDG_CONFIG_HOME:-$HOME/.config}/amnezia-proxy-manager/config`.
Если файл отсутствует, команда сообщает об ошибке; альтернативный файл автоматически
не ищется. Относительный `--config` считается от текущего каталога.

```bash
./amnezia-proxy-manager --config ./local.conf config validate
./amnezia-proxy-manager --config ./local.conf start
```

Строки имеют вид `KEY=value`; внешние одинарные/двойные кавычки снимаются.
Комментарии пишутся на отдельных строках, начиная с `#`. Подстановки shell,
escape-последовательности и inline-комментарии не исполняются/не разбираются.
Неизвестные и повторные ключи, управляющие символы и незакрытые кавычки запрещены.
Числа — десятичные, без ведущих нулей. Регистр ключей значим.

Defaults ниже применяются при отсутствии ключа. Пустое значение допускается
только для соответствующих необязательных параметров. Значения ключей конфига
не наследуются из одноимённых env-переменных. `config validate` работает офлайн,
без sudo и создания runtime-файлов. Шаблон требует заполнения пользовательских
ключей/кредов перед проверкой.

Изменения применяются через `restart`. `stop` использует ownership-состояние;
`status`, `diagnose` и `run` при наличии нового session-снимка проверяют активный
режим, даже если исходный конфиг изменён или удалён.

## Компоненты и общая политика

| Переменная | По умолчанию | Значения и назначение |
|---|---|---|
| `VPN_ON` | `true` | Включить VPN. Принимает `true/false`, `on/off`, `1/0`, только нижний регистр. |
| `PROXY_ON` | `true` | Включить локальный 3proxy с upstream. Те же булевы значения. |
| `BLOCK_IPV6` | `on` | `on/off`. При `on` блокируется исходящий IPv6 всех локальных процессов хоста, кроме loopback. Политика действует независимо от VPN_ON. |

| VPN | Proxy | Результат |
|---|---|---|
| Включён | Включён | 3proxy → управляемый VPN → upstream; маршрут и transport guard обязательны. |
| Включён | Выключен | Только VPN с выбранными маршрутами; proxy-поля не обязательны. |
| Выключен | Включён | 3proxy → upstream через системную маршрутизацию; VPN-поля не обязательны. |
| Выключен | Выключен | Ошибка конфигурации: запускать нечего. |

Проверяются синтаксис всего файла и семантика включённых компонентов.
VPN_LINK при выключенном VPN не декодируется. В proxy-only системный маршрут
может проходить через внешний VPN, но менеджер не обещает его защиту.
В совместном режиме ошибка VPN не включает автоматический обход.

BLOCK_IPV6=on требует nftables/sudo даже в proxy-only. При явно заданном off
proxy-only не требует этих привилегий для обычного start; sandbox всё равно
требует sudo. Отключённая блокировка не добавляет поддержку IPv6 endpoint/upstream.
Диагностика трактует BLOCK_IPV6=off как неполную защиту (код 2).
Полного IPv4 kill switch для хоста менеджер не предоставляет.

## VPN: подключение и ключи

Параметры этой секции используются при VPN_ON=true.

| Переменная | По умолчанию | Значения и назначение |
|---|---|---|
| `WG_INTERFACE` | Нет, обязательна | Имя создаваемого интерфейса, 1–15 символов из латинских букв, цифр, `_`, `=`, `+`, `.`, `-`; одиночные `.` и `..` запрещены. Чужой интерфейс не захватывается. |
| `VPN_LINK` | Пусто | Ссылка `vpn://` из Amnezia/панели. При наличии переопределяет ручные ключи, ADDRESS, ENDPOINT и обфускацию. |
| `PRIVATE_KEY` | Нет | Base64-ключ 32 байт. Обязателен при отсутствии VPN_LINK. Секрет. |
| `PUBLIC_KEY` | Нет | Base64-ключ сервера 32 байт. Обязателен при отсутствии VPN_LINK. |
| `PRESHARED_KEY` | Пусто | Дополнительный Base64-ключ 32 байт; оставить пустым, если сервер не использует PSK. Секрет. |
| `ADDRESS` | Нет | IPv4/CIDR интерфейса; несколько адресов можно разделять запятыми. Обязателен при отсутствии VPN_LINK. |
| `ENDPOINT` | Нет | `IPv4:порт` или `hostname:порт`, порт 1–65535. Hostname закрепляется за одним A-адресом на время запуска. Обязателен при отсутствии VPN_LINK. |
| `PERSISTENTKEEPALIVE` | `25` | 0–65535 секунд; 0 отключает периодические keepalive после подключения. |
| `WG_MTU` | `auto` | Расчёт awg-quick либо фиксированное значение 576–9000. |
| `VPN_CONNECT_TIMEOUT` | `30` | 1–300 секунд ожидания свежего handshake с выбранным сервером. Обязательная проверка во всех VPN-режимах. |

VPN_LINK декодируется локально через Python: base64url(JSON) или сжатый вариант
`4 байта big-endian длины + zlib(JSON)`. Из ссылки берутся ключи, адрес, endpoint
и обфускация. Ручные значения этих полей игнорируются. WG_INTERFACE, DNS,
WG_MTU, PERSISTENTKEEPALIVE, VPN_CONNECT_TIMEOUT, маршруты и proxy-настройки
сохраняют значения из пользовательского конфига/defaults.

Готовность VPN подтверждается handshake, а не только интерфейсом UP. Для
инициации keepalive временно включается с интервалом 1 секунду, затем
восстанавливается пользовательский PERSISTENTKEEPALIVE. При таймауте или ошибке
проверки запуск отменяется; очищаются ресурсы попытки. Восстановление настроек
и cleanup могут занять дополнительное время. Handshake не гарантирует
работоспособность DNS, серверного NAT или любого внешнего сайта.

### Обфускация AmneziaWG

Значения должны соответствовать серверу. При VPN_LINK извлекаются из ссылки;
отсутствующие поля получают defaults. Совместимость с установленным AWG
проверяется самим AWG; числовые границы ниже — проверки менеджера.

| Переменная | По умолчанию | Значения |
|---|---|---|
| `Jc` | `4` | Целое 0–65535. |
| `Jmin` | `40` | Целое 0–65535, не больше Jmax. |
| `Jmax` | `70` | Целое 0–65535, не меньше Jmin. |
| `S1` | `0` | Целое 0–65535. |
| `S2` | `0` | Целое 0–65535. |
| `S3` | `0` | Целое 0–65535. |
| `S4` | `0` | Целое 0–65535. |
| `H1` | `1` | Число или диапазон `min-max`, границы 0–4294967295. |
| `H2` | `2` | Тот же формат. |
| `H3` | `3` | Тот же формат. |
| `H4` | `4` | Тот же формат; диапазоны H1–H4 не пересекаются. |
| `I1` | Не задано | Строка расширенных параметров AWG; семантику проверяет AWG. |
| `I2` | Не задано | То же. |
| `I3` | Не задано | То же. |
| `I4` | Не задано | То же. |
| `I5` | Не задано | То же. |

## Маршруты и DNS

| Переменная | По умолчанию | Значения и назначение |
|---|---|---|
| `ALLOWED_IPS` | Пусто | IPv4/CIDR через пробелы или запятые. IP без маски означает /32. |
| `IPLIST_URLS` | Пусто | HTTPS-адреса списков через пробелы. Ответ содержит IPv4/CIDR через пробелы, запятые или строки; `#` начинает комментарий в списке. |
| `DNS` | Пусто | IPv4 DNS-серверы, например `1.1.1.1,8.8.8.8`. Пусто сохраняет системный DNS; иначе требуется resolvconf. |

Ручные и удалённые списки объединяются. Если оба пусты, используется 0.0.0.0/0:
весь IPv4 без более специфичных системных маршрутов направляется через VPN.
В выборочном режиме остальной трафик следует системным маршрутам. Ошибка
загрузки списка или отсутствие валидных записей отменяет запуск.

В совместном режиме адреса upstream добавляются автоматически. Настроенные
DNS также добавляются в AllowedIPs. Префиксы объединяются без расширения
множества адресов: удаляются дубликаты/покрытые сети и сливаются соседние CIDR.
Например, четыре адреса 192.0.2.0–192.0.2.3 превращаются в 192.0.2.0/30.
В proxy-only эти настройки VPN не применяются.

## Proxy и HTTP/SOCKS-проверки

Параметры используются при PROXY_ON=true.

| Переменная | По умолчанию | Значения и назначение |
|---|---|---|
| `PROXY_STRING` | Нет, обязательна | `host:port:user:password`. Host — IPv4 или hostname; порт 1–65535. Пользователь и пароль непустые; пароль может содержать двоеточия. Содержит секреты. |
| `LOCAL_HTTP_PORT` | `8081` | HTTP-listener на 127.0.0.1, порт 1–65535. |
| `LOCAL_SOCKS_PORT` | `8080` | SOCKS-listener на 127.0.0.1, порт 1–65535; отличается от LOCAL_HTTP_PORT. Поддерживает TCP CONNECT. |
| `PROXY_PARENT_RETRIES` | `2` | 1–10 попыток обращения к upstream. |
| `PROXY_MAXSEG` | Пусто | TCP_MAXSEG 536–8960 для обхода проблем PMTUD; требуется 3proxy 0.9.6+. |
| `STARTUP_HEALTHCHECK` | `warn` | `off` — пропустить HTTP/SOCKS-проверки; `warn` — предупредить; `strict` — отменить запуск при неуспехе. На обязательный VPN handshake не влияет. |
| `HEALTHCHECK_URL` | `https://api.ipify.org` | HTTPS URL без userinfo для HTTP/SOCKS-проверок, test и проверки доступа из sandbox. Успех — HTTP 2xx; редиректы не принимаются. |

При совместном режиме upstream закрепляется за IPv4 и должен быть доступен
через управляемый VPN. В proxy-only используется системная маршрутизация.
HTTP/SOCKS proxy-проверки не применяются к VPN-only.

## Sandbox и GUI

run требует активный proxy; GUI включается CLI-флагом `--gui`, а не ключом
конфига. Настройки применяются при создании sandbox.

| Переменная | По умолчанию | Значения и назначение |
|---|---|---|
| `SANDBOX_NETNS_NAME` | `apm-sandbox` | Имя namespace, 1–15 символов из латинских букв, цифр, `_`, `=`, `+`, `.`, `-`; одиночные `.` и `..` запрещены. |
| `SANDBOX_VETH_SUBNET` | `10.200.0.0/30` | Выровненная IPv4-сеть /30; адрес хоста base+1, sandbox base+2. |
| `SANDBOX_HIDE_PATHS` | Пусто | Дополнительные абсолютные пути через пробелы, без `..`; скрываются пустыми монтированиями. Пути с пробелами этот формат не поддерживает. |
| `SANDBOX_NO_PROXY` | Пусто | Исключения для NO_PROXY/no_proxy внутри sandbox: через запятую, без пробелов. Не создают маршруты или доступ к host loopback. |
| `SANDBOX_EXPECTED_EXIT_IP` | Пусто | Ожидаемый IPv4 выхода. При несовпадении run отменяется. Требует, чтобы HEALTHCHECK_URL возвращал сам IP, например api.ipify.org. |

Конфиг и стандартные секретные каталоги скрываются автоматически; GUI также
скрывает runtime менеджера с сгенерированными ключами/кредами. GUI предоставляет
доступ к сессионным сокетам и GPU и сохраняет дополнительные группы пользователя.
Это расширяет доступ к хосту. Границы изоляции и примеры Electron-флагов описаны
в [справочнике](REFERENCE.md#режим-gui-run---gui).

## Переменные окружения

Эти переменные задаются в shell, а не в KEY=value конфиге приложения.

| Переменная | Если не задана | Назначение |
|---|---|---|
| `AMNEZIA_PROXY_CONFIG` | Стандартный XDG-путь | Путь к конфигу; --config имеет приоритет. |
| `AMNEZIA_PROXY_STATE_DIR` | `$XDG_STATE_HOME/amnezia-proxy-manager` | Логи и постоянное состояние. |
| `AMNEZIA_PROXY_CACHE_DIR` | `$XDG_CACHE_HOME/amnezia-proxy-manager` | Кэш маршрутов. |
| `AMNEZIA_PROXY_RUNTIME_DIR` | `$XDG_RUNTIME_DIR/amnezia-proxy-manager`, иначе `${TMPDIR:-/tmp}/amnezia-proxy-manager-$UID` | PID, ownership, session.state и сгенерированные конфиги. |
| `XDG_CONFIG_HOME` | `$HOME/.config` | Базовый каталог конфигурации. |
| `XDG_STATE_HOME` | `$HOME/.local/state` | Базовый каталог состояния. |
| `XDG_CACHE_HOME` | `$HOME/.cache` | Базовый каталог кэша. |
| `XDG_RUNTIME_DIR` | Не задана | База runtime; в GUI монтируется каталог пользовательской сессии. |
| `TMPDIR` | `/tmp` для fallback runtime | База временного runtime, если XDG_RUNTIME_DIR отсутствует; также используется стандартными временными утилитами. |
| `NO_COLOR` | Цвет при выводе в терминал | Любое непустое значение отключает цвет. |
| `HOME` | Из окружения пользователя | База стандартных путей, домашний каталог приложения в sandbox. |
| `PATH` | Из окружения пользователя | Поиск зависимостей и команд; явно восстанавливается внутри sandbox после sudo. |
| `NODE_OPTIONS` | Пусто для добавляемых опций | В sandbox к значению добавляется `--dns-result-order=ipv4first`; это предпочтение DNS, не защита от IPv6. |
| `DISPLAY` | Не передаётся явно, если пусто | Адрес X11-дисплея в GUI. |
| `WAYLAND_DISPLAY` | Не передаётся явно, если пусто | Имя Wayland-сокета в GUI. |
| `DBUS_SESSION_BUS_ADDRESS` | Не передаётся явно, если пусто | Адрес пользовательской D-Bus-сессии в GUI. |
| `XAUTHORITY` | Не передаётся явно, если пусто | Путь X11-cookie; существующий читаемый файл монтируется read-only, в том числе из /tmp. |
| `XDG_SESSION_TYPE` | Не передаётся явно, если пусто | Тип GUI-сессии, например wayland/x11; отсутствие не мешает запуску. |

Переопределяемые runtime/state/cache-пути должны быть абсолютными; проверяются
владельцы, права и симлинки. Конфиг и runtime содержат секреты: не публикуйте
их вместе с диагностикой.

HTTP_PROXY/http_proxy, HTTPS_PROXY/https_proxy, ALL_PROXY/all_proxy и
NO_PROXY/no_proxy внутри sandbox формируются менеджером по активным портам
и SANDBOX_NO_PROXY. Значения вызывающего shell не выбирают upstream и не
переопределяют этот endpoint. USER и LOGNAME восстанавливаются из UID.

## Примеры

### VPN-only через ссылку Amnezia

```ini
VPN_ON=1
PROXY_ON=0
WG_INTERFACE=amnw0
VPN_LINK="vpn://..."
```

### Только proxy

```ini
VPN_ON=0
PROXY_ON=1
BLOCK_IPV6=off
PROXY_STRING="203.0.113.10:3128:user:password"
```

Здесь off явно отключает общую блокировку IPv6. Для совместного режима
включите оба компонента и заполните обе секции; исходная заготовка находится
в [config.example](../config.example).
