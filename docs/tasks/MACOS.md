# Задача: поддержка macOS

Статус: запланировано, реализация не начата. Дата обсуждения: 2026-10-02.

## Цель

Запускать AmneziaWG и локальные HTTP/SOCKS-прокси на macOS через тот же CLI и
формат конфигурации. Поддержать выборочные и полные IPv4-маршруты, диагностику,
блокировку IPv6 и безопасную остановку с восстановлением после аварии.
Сохранить работоспособность и проверки существующей Linux-версии.

## Подход

Оставить общими конфигурацию, разбор IP-списков, генерацию 3proxy-конфига и
оркестрацию команд. Выделить платформенные операции в отдельные реализации
Linux/macOS. После обсуждения Windows запланирован
[переход общего CLI на Go](GO_MIGRATION.md): macOS-реализация использует это ядро.
Предварительную проверку AWG на Mac можно проводить независимо от переноса.

| Область | Необходимая адаптация |
|---|---|
| VPN и маршруты | AWG userspace, реальные имена utun, ifconfig/route; обход endpoint без Linux fwmark |
| Защита соединений | Исследовать PF и отдельные anchors для upstream и IPv6; учитывать существующие правила и состояния соединений |
| Принадлежность ресурсов | Идентификация процессов и туннеля без /proc; защита от повторного использования PID/интерфейса |
| Runtime и файлы | Блокировки, таймауты, BSD stat, права каталогов и восстановление после аварии |
| DNS и диагностика | Системные средства macOS; проверка listeners, маршрутов, handshake и действующих правил |

## Этапы

1. Проверить зависимости на реальном Mac.
   Зафиксировать рабочие версии AWG tools/Go и 3proxy, совместимость J/S/H/I,
   архитектуру CPU и требования к Bash. Проверить handshake и передачу данных.
2. Выделить платформенный слой.
   Сначала перенести туда Linux-операции и подтвердить существующий тестовый
   набор, затем подключить выбор реализации по ОС.
3. Реализовать запуск на macOS.
   Проверить выборочные маршруты и полный IPv4, прямой путь к endpoint,
   upstream через VPN, DNS и локальные HTTP/SOCKS-listeners.
4. Реализовать защиту и очистку.
   Проверить PF, IPv6, принадлежность ресурсов, частичный запуск, сигналы,
   повторный stop и восстановление после SIGKILL. Ошибка обязательной защиты
   должна запрещать запуск; чужие ресурсы должны сохраняться.
5. Добавить macOS-тесты и инструкции.
   Общие проверки запускать в macOS CI; сетевые сценарии проверять нативно
   на macOS. Linux Docker-тесты не подтверждают работу macOS-сетевого стека.

## Критерии готовности

- Один CLI поддерживает start/stop/restart/status/diagnose/test/logs и config validate.
- Ручные ALLOWED_IPS, IPLIST_URLS и полный IPv4 работают по документированным правилам.
- HTTP и SOCKS передают трафик через upstream, маршрут которого проходит через VPN.
- Удаление туннеля/маршрута не позволяет upstream-соединению перейти в обычную сеть;
  проверены как новые, так и уже установленные соединения.
- BLOCK_IPV6=on реально блокирует внешний IPv6 и сохраняет loopback.
- Остановка и повторная очистка не затрагивают чужие процессы, интерфейсы,
  маршруты, DNS и PF-правила; оставшиеся после аварии собственные ресурсы восстанавливаются.
- Проверены смена Wi-Fi/шлюза и sleep/wake: восстановление или явная ошибка
  без обхода защиты и ложного статуса OK.
- Диагностика различает исправность, ошибку и недоступность проверки.
- Все Linux-проверки продолжают проходить; для macOS опубликованы результаты
  нативных испытаний и список поддерживаемых версий/архитектур.

## Открытые вопросы

- Минимальная версия macOS; Apple Silicon и необходимость поддержки Intel.
- Рабочая поставка AWG: upstream Darwin-скрипт либо собственное управление
  интерфейсом. На дату обсуждения upstream PR с macOS-исправлениями оставался
  открытым; состояние и совместимость нужно повторно проверить перед реализацией.
- Как обеспечить требуемую защиту PF при уже активных правилах других приложений.
- Доступ к Mac и тестовому AWG-серверу для сетевых испытаний.
- Упаковка/Homebrew и launchd — последующие задачи после работающего CLI.
