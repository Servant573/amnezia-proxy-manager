# Установка Linux-версии

Требуются Python 3, make и [зависимости выбранных компонентов](REFERENCE.md#зависимости).
Сборка Bash/Python-кода не требуется. Команды запускаются от обычного пользователя;
sudo используется внутри менеджера для сетевых операций.

## Пользовательская установка

Из каталога исходников:

```bash
make install
export PATH="$HOME/.local/bin:$PATH"
apm --version
```

Добавьте `~/.local/bin` в PATH своего shell. Доступны команды
`apm` и `apm-gui`; длинные `amnezia-proxy-manager` и `amnezia-proxy-gui`
сохранены как дополнительные команды. Создание и заполнение конфига
описано в [README](../README.md) и [справочнике конфигурации](CONFIGURATION.md).
После установки выполните `apm config init`, заполните
созданный файл, затем `config validate` и `doctor` (`doctor --sandbox` для GUI/run).
Установка сама не создаёт конфиг, не запускает VPN и не устанавливает зависимости.
Работа непосредственно из checkout через `./apm` сохраняется.

## Системная установка

```bash
sudo make install PREFIX=/usr/local
```

При конфликте с чужой командой (включая apm) установка отказывает.
Каталоги конфигурации/состояния и AMNEZIA_PROXY_* сохраняют прежние имена.

Устанавливаются только программные файлы, шаблон и документация. Настройки,
ключи, runtime, Git, тесты и отчёты аудита в поставку не входят. Пользовательские
конфиги и состояние сохраняют прежние XDG-пути.

## Раскладка и переменные Makefile

| Переменная | Default | Назначение |
|---|---|---|
| `PREFIX` | `$HOME/.local` | Корень установки. Для sudo задавайте явно `/usr/local`. |
| `BINDIR` | `$PREFIX/bin` | Основные команды apm/apm-gui и длинные aliases. |
| `LIBEXECDIR` | `$PREFIX/libexec` | Каталог приложения с неизменяемыми releases и ссылкой current. |
| `DATADIR` | `$PREFIX/share` | Ссылки на шаблон и документацию выбранной версии. |
| `DESTDIR` | Пусто | Корень временной раскладки для сборки пакета. |

Все заданные пути должны быть абсолютными, без `..` и симлинков в родительских
каталогах. Пробелы и кавычки поддерживаются. Системы с symlink-путём для prefix
должны использовать его физический путь. Одинаковые переменные задаются при
install и uninstall.

Каждый состав файлов получает собственный идентификатор в
`$LIBEXECDIR/amnezia-proxy-manager/releases/`. Ссылка current переключается
атомарно после подготовки файлов. Entry points фиксируют физический путь
к своей версии; Python-helper'ы не зависят от cwd или доступности исходников.
Файлы программ имеют права 755, библиотеки и документация — 644. Receipt
с SHA256 позволяет выявить изменённые и посторонние файлы перед заменой/удалением.

```bash
make install PREFIX=/usr DESTDIR=/tmp/amnezia-package
```

DESTDIR не встраивается в пути программы. Такая установка только готовит
раскладку: проверка пользовательских запущенных сессий пропускается, сетевые
операции и sudo не вызываются. Команды из staging-дерева предназначены для
последующей установки по логическому PREFIX, а не для запуска внутри DESTDIR.

## Обновление и откат

1. Завершите все `run` и GUI, использующие sandbox.
2. Выполните `apm stop` прежней версией в своём окружении.
3. Выполните `make install` из новой версии с прежними переменными установки.
4. Проверьте `--version`, `config validate` и запустите нужный режим.

Если runtime содержит PID/ownership/session-записи или занят lock, установка
и удаление отказывают. Сначала завершите восстановление командой stop; не
удаляйте ownership-файлы вручную. Проверяются стандартные runtime-пути текущего
пользователя, AMNEZIA_PROXY_RUNTIME_DIR/XDG_RUNTIME_DIR и стандартные пути
исходного пользователя sudo. При custom runtime передайте его явно установщику.
Эта проверка не гарантирует обнаружение сессий других пользователей или всех
нестандартных окружений: перед системным обновлением остановите их отдельно.

При ошибке подготовки старая выбранная версия сохраняется. Старые каталоги
releases сохраняются до uninstall. Для отката остановите стек и повторите
make install из исходников предыдущей версии. Автоматического обновления нет.

## Удаление

```bash
make uninstall
# Для системной установки:
sudo make uninstall PREFIX=/usr/local
```

Удаляются только собственные команды, ссылки и проверенные release-каталоги.
Конфиг, логи, кэш и runtime не удаляются; чужие/изменённые файлы вызывают отказ.
Родительские каталоги prefix и файл блокировки установщика сохраняются.
